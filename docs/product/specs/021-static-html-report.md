# Spec 021: `tablewatch report`, a static HTML report of a recorded run (I-10)

- **Track:** full (a new CLI command and its exit codes; user strings rendered into HTML; check data in a file meant to be emailed).
- **Size:** S. All of I-10 (C8) for one run; HTML from `run --output html` is a non-goal.
- **Reviewers:** security-reviewer (REFINE Q1–Q3), architect (REFINE Q4–Q5), data-steward (REFINE Q6–Q7 + VERIFY), qa-engineer (VERIFY). ui-engineer not required: nothing in `frontend/`.

## Problem and persona

Sam owns the sales domain and gets no `tablewatch serve`: the checks run as a nightly job on a server
he cannot reach, and nobody will run a web server for him. Today he asks Dana for a screenshot, or reads
`--output json`. Ravi (audit) needs a dated record of what was checked and what it found, one file per
run that can be attached to an evidence pack and opened years later with no tablewatch install. Both
want one file that opens offline, in a browser or an email attachment, and fetches nothing.
Research: Elementary's `edr report --file-path` writes one HTML with its data base64-embedded for a React
app ([docs](https://docs.elementary-data.com/oss/cli-commands)); `dbt docs generate --static` does the
same, at tens of MB ([dbt](https://docs.getdbt.com/docs/building-a-dbt-project/testing-and-documentation/documentation-website/)).
Both need JavaScript, which mail clients strip. Ours is plain HTML with inline CSS and no script; the
300 KB web UI bundle is not reused.

## Behaviour

`tablewatch report [--run ID] [--output-file PATH]` reads the project's results store (the same
`results.url` as `runs`), takes this project's newest run, or the run whose id starts with `ID`, and
writes one HTML document to stdout, or to `PATH` (overwritten, as `run --output-file` does). It needs
no datasource credentials (rule 6) and runs no checks. The document holds:

- **Header:** project name, outcome, started time (UTC, `2026-10-02 06:00 UTC` — the `%Y-%m-%d %H:%M UTC`
  form Slack already uses, spec 019), duration (`12.3s`, the console summary's own form), counts
  (`19 checks: 11 passed, 2 warned, 6 failed, 0 errors`), run id, trigger, host, tablewatch version,
  and `Selected: <text>`, the UI's own `describeSelection` string (`frontend/src/lib/selection.ts`):
  `all checks` for an empty selection, else `paths: checks/sales; tags: finance` (known labels first,
  `; `-joined). `tw run .` records `{"paths": ["."]}` (spec 020), so it reads `Selected: paths: .`,
  not `Selected: whole project` — a new phrase nowhere else in the product.
- **One table, one row per check result, failing first** (fail, error, warn, pass; then by recorded
  order), listed in full — not a count — because an evidence pack must show every check that ran,
  not only the ones that failed (Vision: Ravi needs an audit trail). Columns, in this order: outcome,
  dataset, datasource, check name, expression, value (`display_value`), message, **since**, owner,
  tags, source `file:line`. Grouping runs identity (dataset → datasource) before the check's own
  definition (name → expression) before its result (value → message → since) before accountability
  (owner → tags) before provenance (`file:line`), the same order the console and Slack read in
  (`dataset · expression: value — message (owner: …)`). **Since** uses the per-outcome verb the
  overview already uses (spec 017): `Failing since`, `Warning since`, `Skipped since`, and
  `Could not evaluate since` for `error` — never "Erroring since": `error` means tablewatch couldn't
  tell, not a verdict to be "erroring" about (rule 7). It is followed by an absolute
  `%Y-%m-%d %H:%M UTC` timestamp — never the overview's relative `Sep 19` / `10:05 today`: those
  elisions depend on the viewer's clock and zone, read live by JavaScript the overview has and this
  file does not (and a file opened "years later", per Ravi's use, has no "today" to elide against).
  Blank for `pass`. The start of the streak itself is still `results/state.py`'s rule, as of this run.
- A footer: `Generated by tablewatch 0.1.0 at <UTC time> from run <id>`.

Every user string is HTML-escaped; there is no `<script>`, no external URL, no `<link>`, no image; a
`Content-Security-Policy` meta tag (D3).

## Scenarios

Fixture: `examples/retail` after `tw run` (measured on `7bc8efe`: 19 checks, 6 fail, 2 warn, 11 pass; exit 1), store at the default
`sqlite:///.tablewatch/results.db`. "Run A" is that run; "run B" a second run with the same outcomes.

| id | | given | expected |
| --- | --- | --- | --- |
| R1 | must | `tw report > r.html` after run A (default, whole-project) | exit 0; stdout is one HTML5 document (`<!doctype html>`); stderr empty; header shows run A's id, `fail`, `19 checks: 11 passed, 2 warned, 6 failed, 0 errors`, and `Selected: all checks` |
| R2 | must | R1's file | 19 result rows, all listed (not a count); the 6 fail rows come first, then the 2 warns, then the 11 passes; each row's cells read, in order: outcome, dataset, datasource, check name, expression, value, message, since, owner, tags, `file:line` |
| R2a | must | R1's file, a `fail` row and an `error` row (both open since run A) | the fail row's since cell reads `Failing since 2026-10-02 06:00 UTC` (or this run's actual start); the error row's reads `Could not evaluate since 2026-10-02 06:00 UTC` — never `Erroring since`; every pass row's since cell is blank |
| R2b | must | `tw run checks/sales` then `tw report` | header reads `Selected: paths: checks/sales` |
| R3 | must | `tw report --output-file out/r.html` (dir exists) | exit 0; file written, UTF-8; stdout prints one line `wrote out/r.html (run <12-char id>)` |
| R4 | must | `tw report --run <first 8 chars of run A>` after run B | reports run A, not B |
| R5 | must | `--run zzzz` | `tablewatch: no recorded run of project retail starts with zzzz`, exit 3, nothing written |
| R6 | must | `--run` prefix shared by two runs | `tablewatch: zzz is ambiguous: <id12>, <id12>`, exit 3 |
| R7 | must | fresh project, empty store (or `results.url: sqlite://`) | `tablewatch: no runs recorded for project <name> — run "tw run" first`, exit 3 |
| R8 | must | a check `name: "<script>alert(1)</script> & \"q\""`, owner `a@b" onmouseover="x`, tag `<b>`, a message with `</td>` | rendered as text: the file contains `&lt;script&gt;`, no `<script` tag, no unescaped `"` inside any attribute; the table has 19 rows of 11 cells |
| R9 | must | any report | no `http://`, `https://`, `//` URL, `<link`, `<script`, `@import`, `url(` in the file; the CSP meta tag is present |
| R10 | must | run B, where a check failed in A and B, and another failed in A and passed in B | since = run A's started time; a check that recovered in B shows blank since |
| R11 | must | `tw report --run <A>` after run B | since is as of run A (A's own start for a first failure), never derived from B |
| R12 | must | `PGPASSWORD` unset, a datasource with `password: ${env:PGPASSWORD}` | exit 0 (no credentials needed) |
| R13 | must | a store file that is not SQLite (VERIFY: a missing SQLite file or directory is R7, exit 3, and `report` creates nothing) | one line `tablewatch: could not read the results store: <reason>`, exit 2, no traceback |
| R14 | must | `--output-file` in a missing directory | `tablewatch: could not write out/r.html: <reason>`, exit 2, no traceback |
| R15 | must | the store shared with project `other` whose run is newer | reports this project's newest run only |
| R16 | should | a run with 2,000 results | written in under 2 s; file under 2 MB |
| R17 | must | a check message with a newline, a tab and U+202E | newline kept as a line break; control and bidi characters do not reorder the row (Q2) |
| R19 | must | an `error` result whose stored message names a host and quotes `'N/A'` | the row reads `could not evaluate`; neither the host nor `N/A` appears in the file (D1) |
| R18 | must | `tw report --help` | lists `--run` and `--output-file`; `docs/` and README gain a `report` section |

Exit codes: 0 written; 2 the store or the file could not be read or written; 3 no such run, an
ambiguous prefix, an invalid project, or a usage error. `report` never exits 1: the run's own outcome
is in the file, and the run's exit code was given when it ran (Q4).

## Non-goals

- `tw run --output html` (a reporter over a live `RunResult` with no history); a later slice.
- A multi-run or trend report, charts, check detail pages, compiled SQL, YAML source.
- Failed-row samples (B6/C7, Phase 2b); there is no row data in the store to show.
- Sending the report (email, Slack, S3); a default output path or directory in the project.
- Any JavaScript, sorting or filtering in the page; theming; a dark scheme beyond `prefers-color-scheme` CSS.
- A new dependency (no Jinja2): stdlib `html.escape` and string building.

## Decisions (REFINE: Q1–Q3 security, Q4–Q5 architect, Q6–Q7 data-steward)

- **D1 (Q1, R1–R2).** An `error` row's message is always the fixed `could not evaluate`
  (`notify/payload.py` `ERROR_MESSAGE`), never the stored text or its first line; the reason stays in
  the store and `serve`. `fail`/`warn` messages are shown. The header shows the host, never the username,
  and nothing from `results.url`. New scenario R19: an error message holding a host name and a quoted
  value appears nowhere in the file.
- **D2 (R3, R5).** Every store field is untrusted (the store can be shared): `html.escape(quote=True)`,
  user strings only as element text, and the outcome's CSS class from a fixed allowlist (an unknown
  outcome gets a neutral class). Before escaping, C0/C1 controls except LF, U+200E/200F, U+202A–202E,
  U+2066–2069 and U+2028/2029 become a space. LF becomes `<br>`. Cells use `unicode-bidi: isolate`.
  R17 becomes a must.
- **D3 (R4).** CSP `default-src 'none'; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'`.
  No `<base>`, `<form>`, `<meta http-equiv=refresh>` or `<img>`.
- **D4 (R6).** The file is written via `tempfile.mkstemp` (0600) in the target directory, then
  `os.replace`. That replaces a symlink rather than writing through it, and never leaves a half-written
  file. Any OSError gives R14's one line and exit 2.
- **D5 (Q4).** `output/html_report.py` holds frozen `ReportView`/`ResultView` (from store rows,
  `view_from_rows`) and `render(view) -> str`, with no server/ wire models. "Since as of run X" comes from
  `latest_results(project, as_of=PageKey)`, a new inclusive bound beside `_older_than`, so
  `current_state` stays the one rule. `report` exits 0/2/3, never 1; this is documented in the
  `cli/main.py` docstring.
- **D6 (Q5).** `ResultStore.matching_run_ids(project, prefix, limit=10)` is project-scoped and
  lowercases the prefix. `store.run` reads the single match, and `runs_page(limit=1)` gives the newest.
- **D8 (VERIFY, QA).** `report` only reads: it never creates a store or its directory. A missing SQLite store is "no runs recorded" (R7), and `--run ""` is a usage error (exit 3). R18's docs are the README section.
- **D7 (Q6, Q7).** The data-steward's wording above, as written.
